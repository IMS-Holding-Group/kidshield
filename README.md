# KidShield – Child Digital Safety System

## فكرة المشروع

KidShield هو نظام متكامل جاهز للإطلاق يهدف إلى حماية الأطفال من المخاطر الرقمية عبر تحليل المحتوى النصي الذي يتعرض له الطفل. يستخدم النظام الذكاء الاصطناعي المتقدم مع تفسير القرارات لتصنيف النص إلى مستويات خطورة دقيقة (منخفضة، متوسطة، عالية)، مع تخزين جميع النتائج وعرضها للأهل عبر تطبيق Flutter، وإنشاء تنبيهات ذكية مع نظام حالات متكامل.

### لماذا KidShield مفيد؟

- **حماية حقيقية**: نظام خطورة متدرج يساعد الأهل على اتخاذ قرارات مستنيرة
- **شفافية**: تفسير واضح لكل قرار يوضح لماذا تم تصنيف المحتوى كضار
- **إدارة متعددة**: دعم عدة أطفال مع تتبع منفصل لكل طفل
- **إحصائيات عملية**: نظرة شاملة على الأنماط والمخاطر
- **جاهزية للإطلاق**: معالجة أخطاء شاملة، واجهة مستخدم محسّنة، منطق احترافي

## المزايا الرئيسية

### التحليل والتصنيف
- **تحليل نصي متقدم**: استخدام TF-IDF + Logistic Regression مع تدريب مكثف
- **نظام خطورة حقيقي**: تصنيف المحتوى بناءً على Risk Score إلى ثلاثة مستويات:
  - **Low Risk** (خطورة منخفضة): confidence < 0.3
  - **Medium Risk** (خطورة متوسطة): confidence 0.3-0.75 أو نمط واحد ضار
  - **High Risk** (خطورة عالية): confidence ≥ 0.75 أو نمطين أو أكثر
- **تفسير القرار (Explainability)**: عرض الكلمات المؤثرة والسبب الواضح لكل تصنيف
- **دعم متعدد اللغات**: تحليل النصوص العربية والإنجليزية
- **تصنيف دقيق**: تحديد فئات محددة للمحتوى الضار (تنمر، كراهية، ألفاظ غير لائقة، تهديد، تحرش)

### إدارة الأطفال (Child Management)
- **إدارة كاملة للأطفال**: إضافة، عرض، وحذف الأطفال مع معلومات العمر
- **ربط التحليلات**: كل تحليل مرتبط بطفل محدد عبر child_id
- **فلترة ذكية**: عرض وتحليل محتوى كل طفل بشكل منفصل
- **إحصائيات لكل طفل**: عدد التحليلات لكل طفل

### التنبيهات والإحصائيات
- **نظام حالات التنبيهات**: 
  - **New**: تنبيه جديد غير مقروء
  - **Reviewed**: تمت مراجعته
  - **Ignored**: تم تجاهله
- **تنبيهات فورية**: إنشاء تنبيهات تلقائية عند اكتشاف محتوى متوسط أو عالي الخطورة
- **إحصائيات عملية**:
  - عدد النصوص المحللة
  - توزيع مستويات الخطورة (Low/Medium/High)
  - المحتويات الضارة خلال آخر 7 أيام
  - أكثر مستوى خطورة تكرارًا
  - أكثر طفل تعرضًا للمخاطر
  - أهم أسباب التنبيهات
  - متوسط Risk Score

### واجهة المستخدم (UX)
- **تصميم أكاديمي**: واجهة واضحة ومنظمة مناسبة لمشروع تخرج
- **تنقل سهل**: BottomNavigationBar للتنقل بين الأقسام الرئيسية
- **بطاقات إحصائية**: عرض المعلومات المهمة في Dashboard
- **عدّاد أحرف**: متابعة طول النص المدخل ديناميكيًا
- **خيارات متعددة**: حفظ فقط أو تحليل وحفظ
- **رسائل خطأ واضحة**: معالجة شاملة للأخطاء مع رسائل مفهومة
- **Loading Indicators**: مؤشرات تحميل في جميع العمليات
- **تأكيدات**: تأكيد قبل الحذف أو الإجراءات المهمة
- **حالات فارغة**: رسائل واضحة عند عدم وجود بيانات
- **سجل زمني ذكي**: تجميع السجلات حسب التاريخ مع تمييز الأيام الخطرة

## تشغيل المشروع

### 1. تشغيل Backend (Flask)

1. الانتقال إلى مجلد backend:
```
cd backend
```

2. تثبيت المتطلبات:
```
pip install -r requirements.txt
```

3. تدريب النموذج (مهم جداً - يجب تنفيذه أولاً):
```
python model/train_model.py
```

**ملاحظة مهمة:** النموذج يتم تدريبه بشكل مكثف وقوي على البيانات باستخدام:
- TF-IDF Vectorizer مع 10,000 ميزة
- N-grams من 1 إلى 3
- Logistic Regression محسّن
- Cross-validation للتأكد من الدقة
- معالجة متقدمة للنصوص

سيستغرق التدريب بعض الوقت حسب حجم البيانات. بعد الانتهاء، ستظهر تقرير شامل بالدقة والنتائج.

4. تشغيل الخادم:
```
python app.py
```

الخادم سيعمل على العنوان: http://localhost:5000

### 2. تشغيل Frontend (Flutter)

1. الانتقال إلى المجلد الرئيسي:
```
cd ..
```

2. تثبيت الحزم:
```
flutter pub get
```

3. تشغيل التطبيق:
```
flutter run
```

## تجربة المناقشة (العرض الحي)

يُنصح بفصل خطوة العرض في المناقشة عن الاستخدام اليومي التقليدي. أدناه **سيناريو واحد** يوضّح: مراقبة من جهاز الطفل → تحليل في الخادم → وصول نتيجة **لحساب ولي الأمر** (تنبيه داخل التطبيق + إشعار نظام **محاكاة**).

### الفكرة باختصار

| العنصر | الجهاز/الواجهة | الدور |
|--------|----------------|--------|
| **طفل** | واجهة `ChildMainScreen` بعد اختيار «دخول طفل» | إدخال نص (أو سيناريو مماثل) وتحديد **التطبيق المصدر** (مثل واتساب) — يُرسل التحليل للخادم مرتبطاً بحساب الأب. |
| **ولي أمر** | واجهة `MainScreen` الاعتيادية | استقبال **التنبيهات** في تبويب «التنبيهات»، و**سناكبار** داخل التطبيق، و**إشعار في شريط إشعارات النظام** (محاكاة وصول إشعار لحساب الأب) عند ظهور تنبيه جديد. |
| **الخادم** | Flask + SQLite | تصنيف النص (نموذج مدمج من عدة مصادر) وحفظ السجل وإنشاء التنبيه **تحت `user_id` لولي الأمر**. |

### الحسابات التجريبية (يُولَّدان عند أول تشغيل للخادم إن وُجدت `init_db`)

- **ولي أمر (للتجربة):** `parent_demo` / `parent123`
- **طفل (للتجربة):** `child_demo` / `child123` (مرتبط بـ`parent_demo` في قاعدة البيانات)
- **مسؤول قديم (اختياري):** `admin` / `admin123`

> في شاشة تسجيل الدخول: اختر **«ولي أمر»** لحساب الأب و**«طفل»** لحساب الطفل (يتم رفض دخول نوع الحساب الخاطئ مع رسالة توضيحية).

### سيناريو المناقشة (خطوة بخطوة)

1. **تشغيل الباكند** من مجلد `backend` (`python app.py`) بعد تدريب النموذج إن لزم.
2. **جهاز/محاكي «الطفل»:** تثبيت التطبيق → تسجيل دخول **طفل** (`child_demo` / `child123`) → تبويب **«المراقبة»** → اختيار **التطبيق المصدر** (مثلاً واتساب) → لصق **نص يُرجّح أن يصنف ضاراً/متوسط/عالي** (مثلاً مفردات من نطاق التنمر في النموذج) → **تحليل وحفظ**.
3. **جهاز/محاكي «ولي الأمر»** (أو نفس الحاسوب بمحاكي ثانٍ): تسجيل دخول **ولي أمر** (`parent_demo` / `parent123`) → منح **صلاحية الإشعارات** عند طلب النظام.
4. **النتيجة المتوقعة للجمهور:** خلال **حوالي 10–15 ثانية** (فترة الاستطلاع في تطبيق الأب) يظهر: **تنبيه** في قسم «التنبيهات» مع **الوقت** و**السبب** و**المصدر (التطبيق)**، **رسالة داخلية (SnackBar)**، و**إشعار في شريط الإشعارات** كمحاكاة ل«وصول الحدث لتطبيق الأب».
5. **الإحصائيات:** من لوحة الأب يمكن فتح **الإحصائيات** لروية **تقارير أسبوعية/شهرية** وتوزيع التطبيقات (حيث يُسجّل `source_app`).

### الاتصال بالشبكة (مهم)

- **محاكي أندرويد** يتصل بـ`localhost` عبر: `http://10.0.2.2:5000` (مضبوط في `api_service.dart`).
- **هاتفان حقيقيان على نفس الشبكة:** عيّن في `api_service.dart` الحقل `baseUrl` إلى **عنوان IP للحاسوب** الذي يشغّل Flask (مثل `http://192.168.1.10:5000`) على **كلا** التثبيتين (أو استخدم `adb reverse` لجهاز واحد).

### ماذا تُوضح للمناقش؟ (جملة جاهزة)

> «المراقبة تتم من سياق يمثّل جهاز الطفل؛ التحليل والتخزين في الخادم مرتبطان بحساب ولي الأمر؛ ويستقبل الأب التنبيه داخل التطبيق مع **محاكاة إشعار نظام** دون الاعتماد بعد على خادم دفع خارجي (FCM).»

### الأقسام الرئيسية

#### 1. لوحة التحكم (Dashboard)
- **بطاقات إحصائية**: عدد النصوص المحللة، المحتويات الضارة، آخر تنبيه
- **سجل المحتوى**: عرض جميع التحليلات مع:
  - مستوى الخطورة (Low/Medium/High) بألوان مميزة
  - Risk Score و Confidence Score
  - السبب والتفسير الواضح
  - اسم الطفل المرتبط

- **إدخال الطفل**: اختيار طفل من القائمة أو إدخال اسم جديد
- **إدخال النص**: حقل نصي متعدد الأسطر مع عدّاد أحرف ديناميكي
- **خياران**:
  - **حفظ فقط**: حفظ النص دون تحليل (للمراجعة لاحقًا)
  - **تحليل وحفظ**: تحليل النص فورًا وحفظ النتيجة
- **عرض النتيجة**:
  - مستوى الخطورة مع أيقونة ملونة
  - السبب والتفسير الواضح
  - الكلمات المؤثرة في القرار
  - Risk Score و Confidence Score
  - الفئة المكتشفة

#### 3. التنبيهات (Alerts)
- **عرض التنبيهات**: قائمة بجميع التنبيهات مرتبة زمنيًا
- **تمييز الحالة**: 
  - نقطة حمراء للتنبيهات الجديدة
  - شارة الحالة (New/Reviewed/Ignored)
- **معلومات شاملة**: مستوى الخطورة، السبب، التفسير، اسم الطفل
- **إدارة الحالة**: 
  - زر "تمت المراجعة" للتنبيهات الجديدة
  - زر "تجاهل" لتجاهل التنبيه
- **ExpansionTile**: عرض النص الكامل عند التوسيع

#### 4. إدارة الأطفال
- **إضافة طفل**: اسم الطفل والعمر (اختياري)
- **قائمة الأطفال**: عرض جميع الأطفال مع عدد التحليلات لكل طفل
- **حذف طفل**: مع تأكيد قبل الحذف
- **معلومات لكل طفل**: الاسم، العمر، عدد التحليلات

#### 5. الإحصائيات
- **إحصائيات شاملة**:
  - إجمالي التحليلات
  - توزيع مستويات الخطورة (Low/Medium/High) مع النسب
  - عدد التنبيهات (الإجمالي وغير المقروء)
  - متوسط Risk Score
  - المحتويات الضارة خلال آخر 7 أيام
  - أكثر مستوى خطورة تكرارًا
  - أكثر طفل تعرضًا للمخاطر

### 2. إدارة الجلسة – `session_service.dart`

```dart
static const _keyUserId = 'session_user_id';

static Future<void> saveSession(int userId) async {
  final prefs = await SharedPreferences.getInstance();
  await prefs.setInt(_keyUserId, userId);
}
```

- **SharedPreferences** لتخزين `userId` محلياً بعد تسجيل الدخول.
- **getSession()** يُرجع `userId` إن وُجد، و `null` إن لم يوجد.
- **clearSession()** يُستخدم عند تسجيل الخروج لمسح البيانات المحفوظة.

#### مسار `/analyze_text`

1. التحقق من صلاحية البيانات.
2. في حالة `save_only`: حفظ النص دون تحليل.
3. تحميل النموذج عبر **classifier.load_model()**.
4. استدعاء **classifier.predict(text)**.
5. تخزين النتيجة.
6. إنشاء تنبيه إذا كان `risk_level` متوسط أو عالي.

#### جلب بيانات الوسائط – `_fetch_media_metadata()`

- يوتيوب: استخدام **oEmbed API** لاستخراج العنوان واسم القناة.
- مواقع أخرى: BeautifulSoup لاستخراج `meta title` و `meta description`.

### 11. مصنّف النص – `backend/model/text_classifier.py`

#### معالجة النص – `preprocess_text()`

```python
text = text.lower()
text = re.sub(r'http\S+', '', text)   # إزالة الروابط
text = re.sub(r'\@\w+|\#\w+', '', text)  # إزالة @ و #
text = re.sub(r'[^\w\s]', ' ', text)  # إزالة علامات الترقيم
text = re.sub(r'\s+', ' ', text)      # دمج المسافات
```

#### كشف الأنماط الضارة – `detect_toxic_patterns()`

- مقارنة النص بقوائم كلمات ضارة عربية وإنجليزية.
- الفئات: تنمر، كراهية، ألفاظ غير لائقة، تهديد، تحرش، عنف.
- يُرجع قائمة الفئات المكتشفة.

#### حساب مستوى الخطورة – `_determine_risk_level()`

```python
pattern_weight = min(len(patterns) * 0.18, 0.5)
confidence_weight = confidence * 0.7
total_score = confidence_weight + pattern_weight
# high: total ≥ 0.7 أو 3 أنماط أو أكثر أو نمط عالي خطورة
# medium: total ≥ 0.45 أو نمطان
# low: total ≥ 0.25 أو نمط واحد
```

#### استخراج الكلمات المؤثرة – `_extract_keywords()`

- استخدام معاملات Logistic Regression (`model.coef_`).
- حساب درجة كل كلمة = `coef * tfidf_value`.
- ترتيب الكلمات حسب التأثير وإرجاع أهم 5.

### 12. تدريب النموذج – `backend/model/train_model.py`

```python
df['is_toxic'] = df[['toxic', 'severe_toxic', 'obscene', ...]].max(axis=1)  # دمج أعمدة السمية
vectorizer = TfidfVectorizer(max_features=10000, ngram_range=(1, 3), ...)
model = LogisticRegression(class_weight='balanced', max_iter=2000, ...)
```

- **TfidfVectorizer**: تحويل النص إلى متجهات، حتى 10000 ميزة، n-grams من 1 إلى 3.
- **class_weight='balanced'**: موازنة الفئات في حالة اختلال التوازن.
- حفظ النموذج و الـ vectorizer باستخدام **joblib** لتشغيله لاحقاً في التطبيق.
